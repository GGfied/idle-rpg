## Harness
- tests/e2e/lib.mjs (withGame/forEachViewport/check/report, g.tapObject/tapTile/teleport/setInventory/chatCount/trackMoves) is the base for NEW scripts: copy TEMPLATE.e2e.mjs (orbs.e2e.mjs = reference, :5205, ~25 s). Pass forEachViewport(...) result AS the withGame callback; withGame exits the process itself. g.rect() returns CENTRE x,y (+left/top/w/h): don't add w/2. g.state() = game slice, g.store() = ROOT. targets() covers WORLD_TREES/OBJECT_SPAWNS/NPC_SPAWNS but NOT rocks or fishing spots. setInventory REPLACES inventory (include the tool). g.eval returning a Phaser object throws "reference chain too long": append `, 0`. g has no cdp handle: g.screenshot + SHOTS_DIR. Store expr scope is `s`.
- cdp.mjs watchdogs: E2E_MAX_MS 6 min -> exit 3, E2E_IDLE_MS 120 s -> "E2E STUCK" exit 4, 20 s per-send timeout (E2E_CDP_TIMEOUT_MS), Chrome exit rejects pendings; exports runMain/waitFor/activity. Never pkill in proofs. Top-level await on a never-resolving promise exits 13: keep a timer alive to test watchdogs.
- launchChrome() takes no flags; a real CDP mouse press is a valid gesture (no autoplay flag). Node 20.18 has no global WebSocket (raw fallback). Phaser 3.90: no Phaser.GAMES; capture the game by wrapping window.Phaser setter, or use window.__idleRpg (store, scene(), setTickMs). scene().camera.scene = WorldScene (vfx, buildings, views, nodes, animator, game reachable); Phaser game = scene().camera.scene.game (loop.sleep/wake freezes a frame).
- CDP quirks: Target.setDiscoverTargets replays the existing page (only close targets with openerId); about:blank localStorage throws SecurityError (clear after navigating); noopener tab reports url "" at targetCreated; setTouchEmulationEnabled needs maxTouchPoints>=1 even when disabling; Browser.setWindowBounds needs clearDeviceMetricsOverride first; headless window height != viewport; no 2nd-tab API: use a same-origin iframe as "tab B" (saves). Count listener leaks by wrapping EventTarget add/removeEventListener in addScriptToEvaluateOnNewDocument.
- Phone = Emulation.setDeviceMetricsOverride mobile + setTouchEmulationEnabled + Input.dispatchTouchEvent (900 ms hold = long-press). CDP touch long-press does NOT fire native contextmenu (hold ends as tap): dispatch a `contextmenu` MouseEvent on the element. dpr capped at 2. Desktop canvas is 998 px (HUD beside it): use the canvas rect. Phone canvas ~480 css px tall: tiles >=3 ahead go off-canvas / under HUD (iso ~48 px/tile): teleport/step near first, tap in 1-2 tile hops. A canvas tap also WALKS the player (teleport back, settle).
- Tick control: `?tickMs=60` (10x), `__idleRpg.setTickMs(600)` for real-time checks (g.realTime); hook clamps 30..600, nothing freezes ticks. Sessions end in ~1 s at 60 ms: wrap in g.realTime or keep-alive re-interact (setInterval) and run each mode phase in its own keep-alive gather. Sound minGapMs is real time. Teleport via store.setState: minimap trail glides ~2 s; same-tile teleport does not recentre follow camera; load() after teleport can keep the old tile.
- Camera settle = lib waitStill(sample) (150 ms between samples, 2 stable intervals); two reads in one rAF look stable while easing. Iso tap point = isoProjection.tileToWorld + camera toClient (window.__e.toClient). Re-sample then tap immediately (canopies sway, points drift).
- Spawn 18,15 is free ground; tile 40,40 blocked taps; fixture tile (12,9) blocked in big world -> loads at spawn.
- Pixel work: decode captureScreenshot in-page; clip {scale} around toClient; sips -c H W --cropOffset y x then sips -z (no PIL). Wrap in-page rAF samplers in try/catch. Spy browser APIs via addScriptToEvaluateOnNewDocument (guard P.__spied): fillText (minimap labels, last frame = after last clearRect), drawImage (worldmap), createOscillator/createBiquadFilter (audio).
- Audio: Phaser has its OWN AudioContext, game's identified by wrapping createDynamicsCompressor; hook AudioNode.connect to find master gain; assert area change via fade-in ramps not osc counts. Axe hit = triangle 105-230 only; music chords are sine 485-550; ambience beds identified by BiquadFilter type:freq.
- Prefs storage `{version, prefs}` written only on first change. Selectors: [data-slot-index=N], [role=menu], .menu-item, .slot[data-selected], .use-hint, [role=dialog][aria-label=Bank] (Close button text), img.dialogue-avatar-img, .dialogue-main/.dialogue-choice/.dialogue-rest, radios via radiogroup aria-labelledby text (scrollIntoView then real tap), canvas.minimap. Bank slots by aria-label. `data-folded`/`data-min` read true on desktop even when expanded: assert desktop layout via computed style. Phone panel scrolls inside .hud-body (assert rect within innerHeight). `pointer-events:none` on a button = tap falls through. Native `disabled` button swallows taps. Inventory tab active at boot: tapping the ACTIVE tab collapses the panel. On phone the bank panel covers most of the canvas.
- Back/front facing: force it through the animator API (or wrap pv.setBackView in-page to read); walking to a tree does not control arrival facing.
- 2026-10-08 FAST BASE (lib.mjs header lists it): runParallel(import.meta.url, port, {viewports, renderers:['webgl','canvas'], budgetMs}) + forEachCombo + withGame({budgetMs, realTime, renderer}) + g.synth.{freeze,step,stepTo,frames,animSeries,thaw} + g.waitState/waitChat/waitIdle/settle/teleportSettled/setLevels/setTickMs/every. Self-test: fastBase.e2e.mjs. DEV hook setTickMs CLAMPS 30..600 (main.tsx clampTickMs): it can NOT freeze ticks (older note "3600000 freezes" is stale); synth.freeze only sleeps Phaser's loop. Synthetic clock must start at game.loop.now (not performance.now) or the first step jumps ~15 ms. game.step() does not bump loop.frame; check scene.time.now. Fabricated chat lines need an id or React warns about keys (console check goes red). Boot dominates tiny tests (~7-9 s/page).
- 2026-10-08 Q3-C1 (bank/isoBank/buildings -> fast base, 199/95/91 s -> 29/49/33 s wall under load avg 250): (1) lib check() runs closeOverlays() BEFORE every check, so a check that relied on the previous check leaving the bank/dialogue open goes red ("no Deposit button", "3 dialogue choices"): each check re-opens what it needs. (2) g.load() clears localStorage: a persistence reload is `g.cdp.send('Page.reload')`; wait on the stored save (idle-rpg:save:1, debounced) not a sleep. (3) tickMs:30 (hook minimum) halves walks again vs 60. (4) lib desktop dpr is 1 (old scripts used 1.6): exact-colour minimap dot counts need `Emulation.setDeviceMetricsOverride deviceScaleFactor 1.6`; a loose "yellowish" range also matches the gold bank square (#ffd23f), so don't loosen. (5) old 600 ms-tick sleeps hid real behaviour: tap on wall tile (12,7) walks round the building to (12,6) at fast ticks, assert "never on y=8 alcoves/booths" via trackMoves, not y<9. (6) desktop right-click right after cancelling another menu is swallowed ~every other time (old probe + 6-click diag T T F T F T): retry once and print attempts. (7) bankDepositAll in actions.ts uses core `deposit()`, not `depositAll()`: mutate there. (8) shared helpers for the bank files live in tests/e2e/bankKit.mjs (timed() adds ms to evidence). (9) never prettier-glob `*Bank*.mjs` (hits other slices' files). (10) "Chrome did not start" at load avg 250 = infra flake, rerun once.
- 2026-10-08 (C4): frame SHEETS without screenshots: in ONE page eval do synth.freeze(), then per offset synth.stepTo(t) + ctx.drawImage(gameCanvas, clip...) into an offscreen canvas (same task as the render, so the WebGL buffer is still valid; works for CANVAS too), toDataURL('image/jpeg') once. lightPolish 8 facings x 20 frames in ~1 s/facing. Game ticks cannot run inside that sync loop, so frames past one one-shot anim cycle (~1 s) show the anim ending (player stands on the logs): capture only one cycle. Guard blank frames with a luminance-spread check.
- 2026-10-08 (C4): screenshots taken DURING an in-page frame-series recording (render hook) stall ~650 ms and perturb jitter metrics (nameplateClampPlay p2 reversal right after the stall): keep them outside the recorded window. Replace fixed "record N ms" windows with "wait until N more frames drawn".
- 2026-10-08 (C5, fishArt/nameplateClamp -> fast base): (1) fishing spots hop every 60-120 TICKS = 3.6-7.2 s at tickMs 60, and a hop's ripple/old art lands in nearby clips (a control clip read 81 dark per-mille once): don't slow ticks, push the move timers instead: g.update spots[k].moveTimer = {respawnAt: g.tick + 1e9} (precondition), then assert the spot tile is unchanged after the sample. (2) At 600 ms ticks the follow camera only starts moving on the NEXT tick, so waitStill/settle right after a teleport reads "still" at the OLD view (topIsCanvas false, "covered by HUD"): teleport + settle at fast ticks. (3) g.synth.frames(offsets, {clip, keep:true}) returns b64 per frame and replaces a hand-rolled scene.time.now override; the node idle art reads scene.time.now, which synth.step drives. (4) withCombos (single combo = no second load) is the cheapest wrapper for a runParallel child; lib's built-in 'console' check covers an old "no console errors" check. (5) The region-name banner ("The Wilds", "Willowbrook Bank") draws over spot clips on phone right after a teleport: expected UI, not a bug, but it can sit in a pixel clip.
- 2026-10-08 withGame opts.initScripts: [pageSource] registers spies before the first load (added by C1, additive). Negative checks after a store/DOM action: wait N page rAFs (`new Promise(r => requestAnimationFrame(...))`) mirroring the positive case, not a fixed sleep. Under load avg 150-300 vite takes up to ~40 s to answer: profile with perl timestamps before blaming the test body.
- 2026-10-08 (C3): withGame boots a page AND forEachCombo loads again = 2 full game loads per child (5-15 s each under load). Use `withCombos(opts, COMBOS, fn)` (lib, additive): one load per runParallel child, forEachCombo fallback under E2E_NO_SPLIT (chat 68->30 s, skills 44->10 s). `g.settleRect(css)` = rect WITHOUT scrollIntoView once it stops moving (g.rect scrolls, which breaks "visible without scrolling" checks).
- 2026-10-08 (C3): synthetic frames vs wall-clock state: the render trail (view walk interpolation) and game ticks run on the WALL clock even under g.synth.freeze. Before freezing, wait in real frames until the view has arrived (waitStill on playerView.container, or wait until the tool/act pose shows), else stepped frames still show 'walk' (gait g5 50 deg, animE2 tool never shown). For gather sessions under synth, pause synthetic time while the session restarts (async page loop waiting on state), never step through a dead session.
- 2026-10-08 (C3): the save key is `idle-rpg:save:1` (adapter prefix); a fresh game saves only on progress (saveTrigger: teleport jump counts, 1 s debounce). Old fishing f1 "reload keeps kit" slept 2.5 s and reloaded with NO save (mutant 'regrant every load' would have passed); now teleport + wait for the key.
- 2026-10-08 (C3): tapSpot-style helpers that slow ticks to 600 ms must restore fast ticks BEFORE teleporting: teleportSettled's settle can return before the camera starts following when the view only moves on the next (600 ms) tick -> spot "covered"/off-screen, bank booth at y=-1456.
- 2026-10-08 (C7, trees/fireVisuals/longWalk/minimapLabels/bankBooth5/fishFlash/cameraInset -> fast base): (1) moving to 60 ms ticks speeds up EVERY game timer, not just the one you meant: a fire lit at 600 ms ticks lasted the whole old run but burned out mid-cooking at 60 (v2b no steam, v4a no fire). Push unrelated timers out as preconditions (fire expiresAtTick = tick+1e6, spot moveTimer.respawnAt = tick+1e9). (2) A short-lived state (kneel while lighting) can end between waitFor seeing it and the next CDP read under load: record it with an in-page rAF recorder (first frame where it holds, all fields read in the same frame) and assert the recording. (3) Per-item teleport loops (85 trees x CDP round trips) -> ONE page eval that teleports via __e.set and waits rAFs until the view exists, reading every neighbour already built. (4) Per-dpr runs: add file-local entries to the exported VIEWPORTS object at module top (every runParallel child re-imports it), e.g. VIEWPORTS.mmDesktopDpr2 = {...VIEWPORTS.desktop, dsf: 2}: no lib change. (5) "Minimap settled" = waitStill on the sum of the last complete frame's fillText x/y (it redraws every rAF), replaces 2.8 s glide sleeps. (6) Real taps aimed "2 tiles from a walking player" go stale at 30/60 ms ticks under load (phone ended 8-13 tiles off): slow just that phase (setTickMs(200)) and go back to 30 right after the tap. (7) Removing a settle sleep can silently break EVIDENCE shots (fishFlash clip showed only water): look at the shots after converting; teleportSettled before any player-relative clip. (8) Clamp screenshot clips to innerWidth: an off-viewport clip renders a black strip that looks like a render bug. (9) First run on a never-used port pays a cold dep-optimize (own cacheDir per port): one ~45 s boot timeout seen, the rerun was fine. (10) At 21:53-22:00 the shared-Chrome path in cdp.mjs threw `browserWs.removeEventListener is not a function` (raw WS fallback has no removeEventListener) while another agent edited it: E2E_PER_CHILD_CHROME=1 is the escape hatch; it worked again by 22:05.
- 2026-10-08 (C6, visualSmoke/stacking/water/bigWorldAreas/fernhavenBank/playerLook -> fast base): (1) synth.frames pairs: the follow camera (lerp 0.15, roundPixels off) never stops easing, it drifts sub-pixel for seconds (phone scrollY 478.6721 -> .6706 in two frames) and a fractional scroll resamples baked textures: "Animations Off = identical" read 52-448 px diff. Pin it for the pair: save cam.lerp, cam.lerp.set(1,1), frames, restore. (2) Old fixed sleeps hid races: Page.reload then ready() can answer from the UNLOADING page (set window.__oldPage=1 before reload, wait for !__oldPage && ready()); phone Settings tap re-lays the HUD sheet and the camera inset glides, so a player-centred clip right after closing Settings misses the player (g.settle() after close). (3) Many-CDP-round-trip samplers (120 tileClient per call x 12 candidates) cost 10+ s under load: do them in ONE page eval; predict client points for a settled camera at another tile (client = playerPoint + (world - standWorld) * scale; exact, matched the measured counts) instead of teleport+settle per candidate. (4) Banner/"shown once" over a window: in-page recorder (store.subscribe + MutationObserver) over g.waitTicks(n), not a wall-clock poll. (5) Renderer-independent checks (DOM, logic) run in the webgl combos only; canvas combos run the pixel checks. (6) At load avg 180-225 boot alone is 20-30 s, so a 4-combo visual file needs body < ~30 s to stay under 60 s. E2E_PER_CHILD_CHROME=1 = escape hatch when the shared-Chrome attach path is broken mid-edit.
