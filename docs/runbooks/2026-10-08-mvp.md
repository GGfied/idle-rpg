- **Status:** in progress

- **Owner:** main session

## Goal
First playable build, made entirely by agents: a small tile world (grass, path, water, trees) with
placeholder shape art; click/tap a tile to walk there on the 600 ms tick, with smooth interpolation and
a camera that follows; click a tree to walk next to it and chop with the starting bronze axe; logs go into
the 28-slot inventory; Woodcutting XP/levels in a skills panel; the tree depletes and respawns; chat log
messages; autosave to localStorage and resume on reload. Works on desktop and in a phone viewport.

## Decisions
- Scope (main session, user asked "code 1st mvp" with no scope): one skill (woodcutting) is the smallest
  real game loop. Out of scope: combat, NPCs, story, other skills, PWA/offline, deploys, sound/vfx/animation
  agents (the walk tween is integrator/graphics-level smoothing only).
- Repo starts empty (the user removed the earlier main-session scaffold). `core` re-scaffolds from scratch.
  Versions from the cancelled runbook still hold: Node 20.18 → Vite 6, Vitest 3.x+, React 18, Phaser 3,
  Zustand 5, TS 5 strict, ESLint 9 flat config, path aliases in tsconfig via `vite-tsconfig-paths`.
- Map as ASCII rows in `features/world/data.ts` (Tiled later).
- Starting state: bronze axe in inventory (no equipping needed for the MVP; `equipment.hasTool`
  checks inventory + worn gear).
- Agents run with plain parallel Agent calls (no Workflow; the user hasn't opted into one).
- Phase 2 split into waves (dependencies): inventory/equipment need `items`; persistence needs every slice.
- Tool data is NOT a field on ItemDef: `equipment` owns a ToolDef table keyed by item id string
  (`defineTools`), so items and equipment don't depend on each other's types. Content modules
  (woodcutting) declare their own items and tools.
- Accepted `core`'s lint deviation: core modules other than engine/contracts/utils/skills may import other
  `@core/*` modules (inventory needs items). Strict rule kept on the four foundation modules.
- `build` is `tsc --noEmit` until `index.html` exists; `integrator` restores `tsc --noEmit && vite build`.
- Chopped trees leave a stump that still blocks (OSRS-like), so the collision grid stays static; `map`
  asked, main session decided.
- Wave B started as soon as `items` was verified (it only depends on items), not after all of wave A.
- Each module owns serialize/deserialize for its slice (CLAUDE.md); persistence composes them into save v1.
- The main session verifies with `npm run test -- <folder filter>` (the shell hook blocks commands that
  name `src/` paths).
