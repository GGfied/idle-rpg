# Runbook: Bigger world (seamless chunked map, villages)

- **Status:** blocked (starts when `2026-10-08-mvp.md` AND `2026-10-08-isometric.md` are done; the chunk
  renderer must be built isometric)
- **Started:** 2026-10-08
- **Last updated:** 2026-10-08
- **Owner:** main session

## Goal
Replace the single 40×30 region with an OSRS-style seamless world: one continuous map split into chunks
that load and draw only around the player, with a few distinct areas (the starting village, a forest, a
lake, a second village, room for a mine). No loading screens; the minimap, pathfinding, saving and the camera
work across chunk borders; phones stay smooth.

## Decisions
- USER: seamless chunked world (not separate regions with travel points).
- USER: start after the MVP runbook closes.
- No new agent (main recommendation): `map` owns chunk data and area layouts; split off a `level-design`
  agent only if `map` becomes a bottleneck.
- Playable first + wire as you go + QA gate (CLAUDE.md) apply to every step: the current world must keep
  working while chunks are introduced.
- Save change → version bump + migration + fixture test + `defaultValue` (old saves place the player in
  the starting village at their old coordinates).

## Tasks
- [ ] Design note (main session → `map` + `graphics` + `movement` + `performance`): chunk size (e.g.
      32×32 tiles), world coordinates, chunk id scheme, how much loads around the player, budgets
- [ ] `map`: chunked world data (Tiled .tmj or ASCII per chunk), world-coordinate collision across chunks,
      spawns per chunk, named areas; the current village becomes chunk(s) of the new world
- [ ] `graphics`: render only chunks near the camera (one RenderTexture per chunk, pooled), minimap across
      chunks
- [ ] `movement`: A* across chunk borders with a bounded search (long walks = waypoints)
- [ ] `persistence`: save v4 (position in world coords) + migration + fixture; `defaultValue`s
- [ ] `integrator`: chunk load/unload around the player, spawns/trees per chunk, camera bounds = world
- [ ] Content: `map` lays out the forest/lake/second village; `woodcutting` tree mix per area;
      `facilities` bank in the second village; `balance` checks resource-to-level placement
- [ ] `performance`: FPS/memory on phone while walking across many chunks
- [ ] `qa`: e2e walking across chunk borders, save/reload far from spawn, minimap, phone
